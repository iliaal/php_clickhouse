# Local patches against vendored clickhouse-cpp v2.6.2

Anything listed here must be re-applied (or upstreamed and dropped)
when the vendored library is bumped.

## Obsoleted in 2.6.2 (no longer needed)

- `clickhouse/columns/string.cpp`: `memcpy(NULL, 0)` UB guard in `AppendUnsafe`.
  Upstream now includes the `if (str.size() > 0)` short-circuit (with essentially
  the same comment). Dropped from this list.

## contrib/lz4/lz4/lz4.c: avoid null-pointer arithmetic for empty dictionaries

The bundled LZ4 computes `dictionary + dictSize` even when the empty-dictionary
state is represented as `dictionary == NULL` and `dictSize == 0`. The resulting
pointer is never dereferenced, but arithmetic on a null pointer is undefined and
Clang's pointer-overflow sanitizer reports it. CI previously disabled
`pointer-overflow` for every extension and vendored translation unit, hiding the
same defect class in binding-owned code.

Patch: the `dictEnd` / `dictBase` hunks are upstream commit `e68c7d3` ("avoid
computing 0 offsets from null pointers", first released in lz4 1.9.3) applied
verbatim -- the vendored copy is 1.9.2 and the line numbers still match. Both
guard on `dictionary == NULL`, so the patch becomes a clean no-op the moment
clickhouse-cpp vendors lz4 1.9.3 or newer rather than a conflict. An earlier
revision of this patch guarded on `dictSize == 0` instead, which diverged from
upstream for `dictionary != NULL && dictSize == 0`. The `prefixEnd` hunk matches
upstream 1.10.0 semantics.

This permits full pointer-overflow instrumentation for the binding and the rest
of the vendored client.

## clickhouse/client.cpp: endpoint rotation stops on malformed handshakes

`Client::Impl::ResetConnectionEndpoint()` retries only `std::system_error`.
After a peer accepts TCP but returns a malformed native handshake,
`ResetConnection()` throws `ProtocolError` and endpoint rotation stops even when
the next configured peer is healthy. The same gap affects initial construction
because `CreateConnection()` delegates endpoint traversal to this method.

Patch: treat any `clickhouse::Error` like a transport failure while traversing
the configured endpoint list. Catching `ProtocolError` alone left `OpenSSLError`
-- its sibling, raised when a TLS peer presents an untrusted or expired
certificate -- aborting rotation. Server exceptions such as authentication
failures still propagate without rotation. `tests/189.phpt` starts a malformed
native peer before the healthy ClickHouse endpoint and verifies constructor-time
failover.

Still not covered: `RetryGuard`'s mid-session rotation loop calls
`ResetConnection()` directly and catches only `std::system_error`, so a
malformed peer reached mid-session aborts rotation and leaves
`current_endpoint_` pointing at the bad peer.

## clickhouse/client.cpp: `Client::Impl::BeginInsert` drops `query_id`

`Client::Impl::BeginInsert(Query query)` constructs the wire-level
`SendQuery` from `query.GetText()` rather than from the full `Query`
object. The implicit `Query(const std::string&)` constructor uses
`Query::default_query_id` (empty), so any `query_id` passed into
`Client::BeginInsert(query, query_id)` is silently discarded and the
INSERT lands in `system.query_log` with an auto-generated id.

The one-shot `Client::Impl::Insert` path is unaffected because it
calls `SendQuery(query)` directly with the `Query` object.

Patch: change `SendQuery(query.GetText())` to `SendQuery(query)` in
`Client::Impl::BeginInsert`.

This is exercised by `tests/028.phpt` (writeStart query_id propagation).

## contrib/cityhash/cityhash/city.cc: unconditional `#include "config.h"`

The vendored cityhash drop ships an unguarded `#include "config.h"`
at the top of `city.cc`. autoconf-style: the file is generated by
the upstream cityhash configure step and defines `WORDS_BIGENDIAN`
and `HAVE_BUILTIN_EXPECT` (both with safe fall-throughs to LE / no
__builtin_expect when undefined).

clickhouse-cpp does not generate one for vendored use, and PHP's
build system does not put a compatible `config.h` on the include
path on Windows (autotools does on Linux only by accident, where
the include resolves but the file's contents end up irrelevant).
The Windows CI build fails with:

```
contrib/cityhash/cityhash/city.cc(30): fatal error C1083:
  Cannot open include file: 'config.h': No such file or directory
```

Patch: gate the include with `HAVE_CONFIG_H` per the standard
autoconf convention. cityhash's downstream defaults are safe; the
file falls through to `__BYTE_ORDER == __LITTLE_ENDIAN` detection
or unconditional little-endian on MSVC.

## clickhouse/client.{h,cpp}: no public `BeginInsert(const Query&)` overload

`Client::Impl::BeginInsert` already takes a `Query`, but the public
surface only exposes `BeginInsert(string)` and
`BeginInsert(string, string)`. That means callers cannot attach
per-query settings, server-side params, or progress callbacks to an
INSERT, even though the impl supports it.

Patch: declare and forward a third overload, `Block
BeginInsert(const Query&)`, so the binding can pass a fully
configured `Query` (settings + params + callbacks + query_id) into
the streaming insert path. Used by `php_clickhouse` to honor
`setSettings()` / per-call settings on `insert()` and `writeStart()`.

## clickhouse/client.{h,cpp}: no public `SelectWithExternalData(const Query&, ...)` overload

`Client::Impl::SelectWithExternalData` already takes a `Query`, but
the public surface only exposes the `std::string` overloads
(`SelectWithExternalData(string, externals, cb)` and
`SelectWithExternalData(string, query_id, externals, cb)`). That
means callers cannot attach per-query settings, server-side params,
or progress / verbose callbacks to a SELECT-with-external-data, even
though the impl supports it.

Patch: declare and forward a thin overload,
`void SelectWithExternalData(const Query& query, const ExternalTables& external_tables);`,
so the binding can pass a fully configured `Query` (settings + params
+ OnData + query_id + OnProgress) into the external-data SELECT path.
Used by `php_clickhouse::selectWithExternalData()` to honor
`setSettings()` / per-call settings and to thread `query_id` through
`system.query_log`. Exercised by `tests/095.phpt`, `tests/096.phpt`,
`tests/097.phpt`.

## clickhouse/client.cpp: `Client::Impl::ResetConnection` clears insert state too late

`ResetConnection()` performs the socket connect *before* clearing the
inserting / Inserting state. When the reconnect throws (server at
`max_connections`, ephemeral-port exhaustion, DNS blip — all cases
where the original dirty socket may still be healthy), the state
remains Inserting. The very next `delete client` (or ~Impl) runs
`EndInsert()` — sending the terminating empty block down the still-dirty
wire and silently committing a partially-streamed insert that the
caller never finished with `writeEnd()`.

(Note: 2.6.x refactored the old `bool inserting_` to a `State` machine
with `State::Inserting`; the logical issue is identical.)

Patch: set `state_ = State::Idle;` (or equivalent) at the very first
line of `ResetConnection()`, before the `connect()` / `InitializeStreams()`
call, so a failed reconnect still neutralizes the destructor's implicit
`EndInsert()`.

Exercised by `tests/123.phpt` (dirty-insert reconnect-failure recovery).

## clickhouse/client.cpp: `ResetConnection()` cannot recover after endpoint exhaustion

The query retry path clears `current_endpoint_` after every configured endpoint
fails. A later explicit `Client::ResetConnection()` unconditionally calls
`current_endpoint_.value()`, so a server that has recovered cannot be reached
through the same client; the method throws `std::bad_optional_access` instead.

Patch: when no current endpoint exists, route `ResetConnection()` through
`ResetConnectionEndpoint()` so it selects from the configured endpoint list
before reconnecting. The normal current-endpoint reconnect path is unchanged.

Exercised by `tests/198_reset_after_endpoint_exhaustion.phpt`, which drops and
restores a local TCP proxy around a live ClickHouse connection.

## clickhouse/client.cpp: `VariantIndex` aggregate `std::variant` construction breaks VS2019

The 2.6.2 `VariantIndex` trait computes its value from
`std::variant<VariantIndexTag<Ts>...>{VariantIndexTag<T>{}}.index()` —
an aggregate-style construction of a `std::variant` evaluated as a
constexpr non-type template argument.

MSVC 14.29 (Visual Studio 2019, the toolset the **PHP 8.3** Windows lane
uses) rejects it with `C2440: cannot convert from 'initializer list' to
'std::variant<...>'`, failing the whole extension build. VS2022 (PHP
8.4/8.5) and GCC/Clang accept it, so the break surfaced only on the 8.3
Windows binaries — and only in the `release-windows.yml` lane, which runs
after the tag is published. 0.8.6 shipped with no PHP 8.3 Windows DLLs as
a result.

Patch: replace the construction with a `variant_index_of<T, Ts...>()`
helper that folds over `std::is_same_v` and returns the first matching
index. No `std::variant` is constructed; the result is identical and
portable across GCC, Clang, and MSVC 14.29/14.3x. The now-unused
`VariantIndexTag` helper is removed. Good candidate to propose upstream.

The pre-tag gate now mirrors the release Windows matrix (`tests.yml`
`windows-matrix` builds 8.3/8.4/8.5), so a vs16-only break blocks the
release instead of surfacing post-tag. Exercised implicitly by every
packet-loop test (`select`, `insert`, `ping`).

## clickhouse/client.cpp + base/socket: destructor EndInsert hang guard

`Client::Impl::~Impl` calls `EndInsert()` when still `Inserting`. With
`connection_recv_timeout` of 0 (infinite, the extension default), a dead
or half-open peer makes `ProcessPacket` block forever — PHP `unset($ch)`
or request shutdown hangs the worker.

Patch: `0010-Bound-Client-Impl-teardown-when-recv-timeout-is-infi.patch`.
Before destructor `EndInsert`, re-apply socket timeouts with a hard 5s
floor when the configured recv/send timeout is zero. Healthy peers still
finalize within the window (test 091). `Socket::SetTimeouts` is a
best-effort `setsockopt` wrapper that never throws.

Scope limits worth knowing before relying on this:

- The floor only bounds the *infinite* case. A positive configured
  `receive_timeout` is kept as-is, so `receive_timeout => 3600` still
  stalls teardown for an hour.
- The deadline is per `recv()`, not for the whole `EndInsert()`.
- The `catch (...)` swallows the resulting throw. A healthy server that
  goes quiet past the window therefore drops the insert tail with no
  diagnostic -- the trade is a truncated abandoned insert instead of a
  hung worker.
- The trailing `state_ = Idle` in that catch is defensive only. Nothing
  reads `state_` after the destructor body runs.

## clickhouse/base/sslsocket.cpp: peer certificate leaked on failed verification

`SSLSocket::SSLSocket` builds its error message with
`getCertificateInfo(SSL_get_peer_certificate(ssl))`.
`SSL_get_peer_certificate` returns a *new* reference; `getCertificateInfo`
only borrows. Nothing freed it, so every rejected handshake leaked the
peer certificate and its chain -- measured at ~4.4 KB per attempt under
LeakSanitizer, linear in retries. A worker retrying against a
misconfigured or cert-rotating peer grows without bound.

Patch: `0011-Release-the-peer-certificate-on-a-failed-TLS-verific.patch`.
Own the certificate in a `unique_ptr<X509, X509_free>` for the lifetime
of the message build. Exercised by `tests/188.phpt` under the ASAN lane
once that lane is built with OpenSSL.

## clickhouse/client.cpp: `RetryGuard` and `CreateConnection` rotate only on `std::system_error`

`Client::Impl::ResetConnectionEndpoint()` retries any `clickhouse::Error`
(patch 0002 above), but the three remaining rotation sites --
`CreateConnection()` and both `RetryGuard` loops -- catch only
`std::system_error`. A malformed peer reached mid-session throws
`ProtocolError` (or `OpenSSLError` on certificate rotation), aborting
rotation and leaving `current_endpoint_` pointing at the bad peer.

Patch: `0012-Rotate-endpoints-on-Error-in-retry-paths.patch`. Adds a
`catch (const Error&)` alongside each `catch (const
std::system_error&)` with the same recovery body. Mid-query server
exceptions still propagate: the binding's select/execute paths catch
`ServerException` before any reset runs, so this only affects
connection-establishment failures.

## clickhouse/client.cpp: destructor teardown keeps a huge positive timeout

Patch 0010 bounds destructor `EndInsert` with a 5s floor when the
configured recv/send timeout is 0 (infinite), but keeps any positive
configured timeout as-is -- so `receive_timeout => 3600` still stalls
`free_obj` / request shutdown for an hour on a dead peer.

Patch: `0013-Cap-teardown-timeouts-at-5s.patch`. Applies
`min(configured, 5s)` to the teardown recv/send timeouts (plus an
`<algorithm>` include for `std::min`). The floor still covers the
infinite case; a positive-but-huge timeout no longer hangs teardown.

## clickhouse/client.cpp: malformed packets and unbounded ping retries

`ReceivePacket()` mapped failed varints, metadata, and auxiliary packet reads to
`std::monostate`, which callers treated as a clean end-of-stream. This could
silently return partial query results. `ReceiveException()` also published and
threw partially decoded server exceptions, and automatic ping recovery could
loop forever on a peer that completed handshakes but never returned Pong.

Patch: `0014-Bound-protocol-decoding-and-ping-retries.patch`. Packet decode
failures now throw `ProtocolError`; exception callbacks and throws are gated on
complete decoding, including handshake exceptions; and `RetryGuard()` honors
`send_retries` with an immediate failure at zero retries. Exercised by
`tests/217_packet_decode_and_ping_retry.phpt`.

## clickhouse/base/compressed.cpp: compressed sizes below the frame header

`CompressedInput::Decompress()` capped the declared compressed size at
1 GB but had no lower bound. For a frame declaring 0..8 bytes, below the
9-byte method and size header, `BufferOutput` grows the buffer to 9
bytes for the header, and the following
`ReadBytes(tmp.data() + HEADER_SIZE, compressed - HEADER_SIZE)` gets a
`size_t` length that wraps to just under 2^64. The write past the 9-byte
buffer is then bounded only by how many bytes the peer sends. A
malicious or broken server with compression enabled could overflow the
heap with those bytes: ASan reports a heap-buffer-overflow WRITE, and
release builds were observed to abort (SIGABRT, `malloc(): corrupted
top size`), crash (SIGSEGV), or continue with silently corrupted heap
memory when the overflow was only a couple of bytes.

Patch: `0015-Fix-compressed-block-size-validation.patch`. Rejects
`compressed < HEADER_SIZE` with `CompressionError` before allocating,
and both size errors now report the declared size. Exercised by
`tests/222_compressed_frame_header_size.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/566 (commits f0f2927, 1d60058; unreleased as of v2.6.2)

## clickhouse/types/type_parser.cpp, columns/factory.cpp, columns/string.cpp: zero, oversized, and malformed FixedString sizes

A server-supplied `FixedString(0)` type built a `ColumnFixedString` with
`string_size_ == 0`; `Size()` divides by it, so the zero-row header block
already raised SIGFPE in `Block::AppendColumn()`. A malformed width such as
`FixedString(-)` made `std::stol` throw out of `TypeParser::Parse()`, and
`ParseTypeName()`, which inserted the cache entry before parsing and erased it
only when `Parse()` returned false, kept the half-built AST (width 0), so the
next identical type crashed the same way.

Patch: `0016-Reject-zero-and-malformed-FixedString-sizes.patch`. Number tokens
parse with `std::from_chars` and fail the parse when invalid or out of range,
so the existing erase-on-failure path runs; `ParseTypeName()` also parses into
a local and caches only on success, so a parser exception cannot leave an
entry behind. The factory rejects `FixedString` sizes outside 1..0xFFFFFF (the
server's `DataTypeFixedString` `MAX_FIXEDSTRING_SIZE`) with `ValidationError`,
and the `ColumnFixedString` constructor rejects size 0. Exercised by
`tests/249_fixedstring_zero_width_rejected.phpt` and
`tests/250_fixedstring_malformed_width_not_cached.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/577

## clickhouse/types/type_parser.{h,cpp}: bounded parsed type AST cache

`ParseTypeName()` kept every distinct type name it parsed in a process-wide
`std::map` with no eviction, so a peer could grow client memory by sending
many distinct type names, one zero-row block each.

Patch: `0017-Bound-the-parsed-type-AST-cache.patch` (applies on top of 0016).
The cache holds at most `kTypeAstCacheMaxEntries` (4096) entries and
`kTypeAstCacheMaxBytes` (256 KiB) of type-name text; an insert that would
exceed either limit clears the cache first (the old map is destroyed after the
mutex is released), and a longer name is parsed on every call without being
cached. `ParseTypeName()` returns
`std::shared_ptr<const TypeAst>` so an AST still in use survives a clear; the
binding only reaches it through `CreateColumnByType()`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/585

## clickhouse/types/type_parser.cpp: unbalanced and deeply nested type names

`TypeParser::Parse()` called `top()`/`pop()` on its element stack for every
`)` and `,`, so a server- or caller-supplied type name such as `UInt8))`,
`),`, or `)))` read from an empty `std::stack` (release SIGSEGV). The parser
also had no nesting limit, while `CreateColumnFromAst()` and `TypeAst`
destruction recurse once per level, so `Array(` repeated 100000 times (closed
or not) exhausted the native stack.

Patch: `0018-Reject-unbalanced-and-overly-deep-type-names.patch`. `Parse()`
returns false for a `)` or `,` with no open parenthesis and for nesting deeper
than `TypeParser::kMaxNestingDepth` (512; current servers reject column types
nested deeper than 499 levels, and 512 levels keep the recursive paths to
about 250 KiB of stack at -O2); `CreateColumnByType()` then returns null and the
Data-block reader throws `unsupported column type`. Exercised by
`tests/252_type_parser_unbalanced_close.phpt`,
`tests/253_type_parser_depth_limit.phpt`, and
`tests/254_external_type_parser_errors.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/587

## clickhouse/columns/factory.cpp: wrapper types over unsupported nested types

`CreateColumnFromAst()` built `ColumnArray`, `ColumnNullable`, and the
`LowCardinality(Nullable(T))` dictionary around whatever the nested call
returned. For a nested type the factory cannot create (`Array(5)`,
`Array(Null)`, `Nullable(DateTime64)`, `LowCardinality(Nullable(5))`, ...)
that is `nullptr`, and the wrapper constructor dereferenced it. A malicious
or compromised server reaches this with one column type string in a Data or
ProfileEvents block; `selectWithExternalData()` reaches it with a
caller-supplied column type.

Patch: `0019-Reject-wrapper-types-over-unsupported-nested-types.patch`.
Array and Nullable return `nullptr` when the nested column is null, matching
Tuple and Map, so `ReadBlock()` throws `UnimplementedError("unsupported column
type: ...")`. `LowCardinality(Nullable(T))` throws `UnimplementedError`, like
the generic LowCardinality branch. Exercised by
`tests/255_wire_nullable_unsupported_nested_type.phpt`,
`tests/256_wire_array_unsupported_nested_type.phpt`, and
`tests/257_unsupported_nested_type_external_data.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/578

## clickhouse/columns/{string,tuple,nullable}.cpp: FixedString row total overflows

`ColumnFixedString::LoadBody` sized its buffer as `string_size_ * rows` with
no overflow check. A server that declares `FixedString(4611686018427387905)`
with 4 rows wraps the product to 4 bytes: `Size()` then reports 0 rows while
`At()` returns views of the full declared width past the end of the buffer.
`ColumnTuple::LoadBody` and `ColumnNullable::LoadBody` never compare the
loaded child sizes with the requested row count (and `ColumnTuple::Size()`
reports only its first element), so `Tuple(UInt8, FixedString(huge))` and
`Nullable(FixedString(huge))` reached the binding as 4-row columns whose
FixedString reads went out of bounds (SIGSEGV). A plain top-level
`FixedString(huge)` instead returned zero rows for a 4-row block.

Patch: `0020-Reject-FixedString-loads-whose-byte-size-overflows.patch`.
`ColumnFixedString::LoadBody` throws `ProtocolError` when the multiplication
overflows; `ColumnTuple::LoadBody` and `ColumnNullable::LoadBody` throw
`ProtocolError` when an element or the nested column holds a different number
of rows than was loaded. Exercised by
`tests/258_wire_fixedstring_width_overflow.phpt`, with valid shapes covered by
`tests/260_column_load_valid_nested_shapes.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/579

## clickhouse/columns/tuple.cpp: `ColumnTuple::Clear` drops the element columns

In v2.6.2 `ColumnTuple::Clear()` runs `columns_.clear()`, so a cleared Tuple
becomes `Tuple()` and a cleared `Map` (an `Array(Tuple(K, V))`) loses its key
and value columns. Patch 0022 clears the nested column when every Array
offset in a block is 0, which reaches this path for an all-empty `Map`,
`Array(Map(...))`, or `Map` inside a `Tuple`: the binding then dereferenced the
missing elements (SIGSEGV) or rejected the column as `Array(Tuple())`.

Patch: `0021-Clear-Tuple-elements-in-place.patch`, the `ColumnTuple::Clear`
hunk of upstream commit 44f54c5 ("Make composite Swap and Tuple Clear
alias-coherent"), applied verbatim. It clears each element in place. Drop
this backport once the vendored library includes 44f54c5; the Array offsets
patch (0022) needs it until then.
Exercised by the all-empty and mixed Map rows in
`tests/260_column_load_valid_nested_shapes.phpt`.

Upstream: already on master (44f54c5), not in a release yet.

## clickhouse/columns/array.cpp: Array offsets not validated on load

`ColumnArray`'s constructor rejects decreasing offsets and a nested column
whose size differs from the last offset, but `ColumnArray::LoadBody` checked
neither. Server-sent decreasing offsets made `GetSize()` / `GetAsColumn()`
compute `offsets[n] - offsets[n - 1]` with unsigned wraparound; for
`Array(Nothing)`, whose `Slice()` keeps any length, a row reported a length
near 2^64 and the binding died on a huge allocation hint (PHP fatal).

Patch: `0022-Validate-Array-offsets-when-loading-from-the-wire.patch`.
`LoadBody` throws `ProtocolError` on a decreasing offset and when the nested
column does not hold exactly as many values as the last offset; with no rows
or only empty arrays it clears the stale nested values instead of returning
early. Exercised by
`tests/259_wire_array_offsets_decreasing.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/580

## clickhouse/client.{h,cpp}: `ServerInfo` fields a Hello omits stay uninitialized

`ServerInfo` had no default member initializers, and `ReceiveHello()` fills
`timezone`, `display_name`, and `version_patch` only when the server revision is
new enough to carry them. A server announcing a revision below 54401 left
`version_patch` holding indeterminate heap bytes, which `getServerInfo()`
returned; a reconnect to an older server kept the previous server's values.

Patch: `0023-Zero-ServerInfo-fields-a-Hello-does-not-carry.patch`. Default-initializes
every numeric `ServerInfo` member and resets `server_info_` before parsing each
Hello. Exercised by `tests/261_old_revision_hello_server_info.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/581

## clickhouse/client.cpp: ProfileInfo flags read straight into `bool`

`ReceivePacket()` read the `applied_limit` and `calculated_rows_before_limit`
wire bytes directly into `bool` members of `Profile`. A byte other than 0 or 1
produced a `bool` with an invalid object representation, and loading it (for
example in the binding's profile callback) is undefined behaviour. The obsolete
`has_nested` byte in `ReceiveException()` used the same pattern.

Patch: `0024-Read-ProfileInfo-flags-as-bytes-not-bool.patch`. Reads each flag into
a `uint8_t` and stores `byte != 0`; `has_nested` is read as `uint8_t`. Exercised
by `tests/262_profile_info_noncanonical_bool.phpt` and
`tests/263_profile_info_noncanonical_bool_select.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/582

## clickhouse/base/compressed.cpp: decompressed output not validated

A compressed frame declaring an original size of 0 allocated `Buffer(0)`, whose
`data()` is null, and passed that null destination to `LZ4_decompress_safe` /
`ZSTD_decompress`. LZ4 applies offsets to the destination pointer before it
checks the capacity, which is undefined behaviour. A well-formed empty frame
also left the decompressed window empty, so `DoNext()` reported end of stream
instead of reading the next frame. Separately, `Decompress()` ignored how many
bytes the decompressor produced and exposed all `original` bytes, so a
checksum-valid frame that decoded short returned a zero-filled tail as data.

Patch: `0025-Validate-what-compressed-frames-decompress-to.patch`. Decompresses
an empty frame into a one-byte stack target with zero capacity, so a non-empty
payload still fails with `CompressionError`; `DoNext()` keeps reading frames
until one yields data or the input ends; and LZ4/ZSTD output whose length
differs from the declared original size throws `CompressionError`. Applies on
top of patch 0015 (upstream `f0f2927`). Exercised by
`tests/264_compressed_empty_frame.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/586

## clickhouse/base/sslsocket.cpp: TLS handshake not bounded by the connect timeout

`connection_connect_timeout` bounds only the TCP connect poll in
`SocketConnect()`. `SSLSocket::SSLSocket` then ran a blocking
`SSL_connect()`, whose reads are bounded only by `SO_RCVTIMEO` -- the
query receive timeout, infinite by default. A peer that accepts TCP but
never answers the ClientHello blocked the constructor forever, so
endpoint failover never reached a healthy server.

Patch: `0026-Bound-the-TLS-handshake-by-the-connect-timeout.patch`.
`SSLSocket::Handshake()` switches the socket to non-blocking, loops
`SSL_connect()` on `SSL_ERROR_WANT_READ`/`WANT_WRITE` with `poll()`
against a deadline of `connection_connect_timeout` (negative waits
forever, as for the TCP connect), and restores blocking mode afterwards.
Expiry throws `std::system_error(ETIMEDOUT)` (`WSAETIMEDOUT` on Windows),
which every rotation site treats as a connection failure. Adds
`Socket::SetNonBlocking()` and `Socket::WaitFor()`, and documents the
handshake bound on `connection_connect_timeout` in `client.h`. The deadline is per
handshake, so a TLS endpoint can take up to twice the connect timeout
(TCP connect plus handshake). Exercised by
`tests/265_tls_handshake_tarpit_failover.phpt` and
`tests/266_tls_handshake_tarpit_timeout.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/583

## clickhouse/base/sslsocket.cpp: CA-load failures report "Unknown SSL error"

With OpenSSL 3, `ERR_reason_error_string()` returns NULL for system errors,
so a missing or unreadable `ssl_ca_files` entry failed with
`OpenSSL error: -2147483646 : Unknown SSL error` and no path. `throwSSLError()`
also popped one queue entry and left the rest for a later failure to report.
The comment above the disabled `X509_check_ip` block claimed IP addresses are
not verified; OpenSSL 3.0+ `SSL_set1_host()` checks IP literals against the
certificate's IP SANs.

Patch: `0027-Name-the-CA-file-or-directory-when-loading-it-fails.patch`.
Falls back to `ERR_error_string_n()` (which formats errno), prefixes CA
file/directory load failures with the path, clears the error queue before
each CA load and after reporting, and corrects the comment. Exercised by
`tests/233_ssl_ca_path_validation.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/584

## clickhouse/columns/factory.cpp: LowCardinality subtree copies

`CreateColumnFromAst()` bound the `LowCardinality` child as
`const auto nested = GetASTChildElement(ast, 0)`, copying the whole subtree
at every level. A type such as `LowCardinality(Nullable(` repeated 255 times
around a wide `Tuple` held one copy per level during the recursion, so a
server-supplied type of tens of kilobytes drove peak memory to hundreds of
megabytes (outside `memory_limit`) before the type was rejected.

Patch: `0028-Avoid-copying-the-type-AST-at-each-LowCardinality-level.patch`.
Binds the child by `const auto&`; no other `GetASTChildElement()` result in
`factory.cpp` is copied. Exercised by
`tests/272_lowcardinality_nested_ast_memory.phpt`.
Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/588


## clickhouse/base/compressed.cpp: declared compressed-frame sizes

`CompressedInput::Decompress()` allocated `Buffer(compressed)` (capped at
1 GiB) before reading the payload and zero-filled `Buffer(original)` (any
`uint32_t`) before decompressing it. A malicious or compromised server with
compression enabled could make a frame of a few bytes commit up to 1 GiB or
4 GiB of native memory, outside PHP `memory_limit`.

Patch: `0029-Bound-decompressed-sizes-and-read-compressed-frames-as-they-arrive.patch`,
on top of 0015 and 0025. Rejects `original` above 1 GiB, the
`DBMS_MAX_DECOMPRESSED_SIZE` ClickHouse itself applies
(`src/Compression/CompressionInfo.h`); reads the compressed payload in steps
starting at 4 MiB, reserving eightfold ahead and zero-filling only what is
being read; and keeps the decompression buffer uninitialized and reused
across the frames of one packet, so only the bytes the decoder writes are
committed. 0025's check that a frame decompresses to exactly `original` bytes
is what keeps stale bytes of the reused buffer from being returned. Exercised
by `tests/268_declared_compressed_sizes.phpt` and
`tests/269_large_results_load.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/592 (stacked on https://github.com/ClickHouse/clickhouse-cpp/pull/586)

## clickhouse/columns/{numeric,enum,string,lowcardinality}.cpp, base/wire_format.h: declared column and string sizes

`ColumnVector::LoadBody`, `ColumnEnum::LoadBody`, and
`ColumnFixedString::LoadBody` resized to the server-declared row count (times
the FixedString width) before reading, which zero-fills the whole declared
size; `ColumnString::LoadBody` reserved the declared row count and allocated
each declared string length up front; `WireFormat::ReadString` zero-filled up
to 16 MiB per declared length (exception text, column names and types). A
malicious or compromised server could commit gigabytes from a packet of about
40 bytes, outside PHP `memory_limit`.

Patch: `0030-Grow-column-bodies-and-protocol-strings-as-data-arrives.patch`,
on top of 0020. Adds `WireFormat::ReadPODArray`, which starts at 1 MiB,
reserves eightfold ahead (overflow-safe through `NextReadCapacity`), and
zero-fills only what it is about to read, so committed memory tracks the
bytes received. It is used for those column bodies and for `ReadString`.
`ColumnString` caps its initial row reservation at 1 MiB of items, grows it
eightfold, and reads strings above 1 MiB into a dedicated block grown the
same way. The growth copies are not small in the worst case: an 80 MB single
column body copies 73 MiB (1 + 8 + 64 MiB) while growing, about +60 ms of CPU
on the release build; default 64K-row blocks fit the first step and cost
nothing extra. `ColumnLowCardinality` now rejects a short index column
instead of ignoring `LoadBody`'s result, which with incremental loading would
deliver fewer rows than declared. Exercised by
`tests/267_declared_column_sizes.phpt`, `tests/269_large_results_load.phpt`,
and `tests/270_declared_protocol_strings.phpt`.

Upstream: https://github.com/ClickHouse/clickhouse-cpp/pull/591
